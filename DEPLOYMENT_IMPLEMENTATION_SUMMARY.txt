## 🚀 Quick Start

### Deploy in Different Modes
```bash
# All-in-One (single device)
MAP2_DEPLOYMENT_MODE=ALL-IN-ONE ./map2.sh start

# Audio Node (dedicated processing)
MAP2_DEPLOYMENT_MODE=AUDIO-NODE ./map2.sh start

# Control Node (frontend/UI)
MAP2_DEPLOYMENT_MODE=CONTROL-NODE ./map2.sh start

# Frontend Only (lightweight)
MAP2_DEPLOYMENT_MODE=FRONTEND-ONLY ./map2.sh start
```

### Check Status
```bash
# Get current mode
curl http://localhost:8000/api/deployment/mode

# Get health status
curl http://localhost:8000/api/deployment/health/status

# Get discovered peers
curl http://localhost:8000/api/peers
```

### Run Remediation
```bash
# Restart mDNS discovery
curl -X POST http://localhost:8000/api/deployment/remediation/restart_mdns

# Run all health checks
curl -X POST http://localhost:8000/api/deployment/health/checks
```

### Use TUI
```bash
# Open TUI
./tui.sh

# Press 'c' for Cluster tab
# View peers, readiness, actions
# Click buttons for one-click remediation
```

## 🔧 Architecture Highlights

### Config Persistence
```
~/.map2/deployment.json       # Deployment mode & service policies
~/.map2/ssh_trust/trusted_peers.json  # Trusted peer list
~/.ssh/authorized_keys        # Trusted peer public keys
~/.ssh/map2_*                 # SSH key pairs
```

### API Organization
```
/api/deployment/*             # Mode & config (5 endpoints)
/api/ssh/*                    # SSH trust (6 endpoints)
/api/peers/*                  # Discovery & linking (4 endpoints)
/api/deployment/health/*      # Health checks (5 endpoints)
/api/deployment/remediation/* # Actions (2 endpoints)
```

### Service Policies per Mode
```
ALL-IN-ONE:      All services enabled
AUDIO-NODE:      Audio+API enabled, Web disabled
CONTROL-NODE:    API+Web enabled, Audio disabled
FRONTEND-ONLY:   Web enabled, Heavy services disabled
```
