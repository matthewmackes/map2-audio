# React Web Audit — MAP2 Audio Platform

**Date:** 2026-04-28
**Scope:** `web/src/` React codebase (1,259 source files) + production build artifacts
**Method:** Six parallel lens-audits (architecture / fit-for-purpose / dead-code / anti-patterns / latency / build-health), each producing file:line-cited findings with severity and effort.

## Errata (added during execution)

While acting on the punch list, three findings were checked against the actual code and proved to be partially or fully wrong. Corrections:

- **Dead-2a (`viewedNodeStore` orphaned):** ❌ **Incorrect.** The store has ~25 active consumers across pages, hooks, the global nav (`NodeNavBar`/`NodeMiniCard`/`NodeNavChip`), `AppShell`, `PlatformModal`, and every major workspace. It is shared infrastructure that *both* `NodeNavChip` (kept) and `NodeContextPicker` (deprecated) read from. **Do not delete the store.**
- **Punch-list #2 (replace `NodeContextPicker` with `NodeNavChip`):** ⚠️ **Not API-compatible — but resolved.** Reading the global nav showed that `NodeNavBar` already derives `pageKey` from the URL and that clicking any `NodeNavChip` opens a `NodeMiniCard` whose "Set as page node" button writes the same `viewedNodeStore[pageKey]` the workspaces read. So the picker was *redundant* in-page UI, not orphaned-after-replacement. Action taken: removed picker render slots from both workspaces, deleted the picker directory + tests + dead CSS rules, refreshed `DesktopExperience.snapshot.test` (the only diff was cascading `useId()` renumbering after removing two `<Dropdown>` instances).
- **Lat-5 (`useVuMeters` peakHold "spread every 33 ms"):** ⚠️ **Overstated.** The code already gates `setPeakHold` behind a per-channel exceed check, so a new state object is only committed when at least one channel exceeds the prior peak. Real wins: (a) avoid the unconditional `{ ...peakHold }` spread when no channel exceeds, (b) skip the 2-s reset commit when post-decay values match. Severity Low/S, not High/S. **Fixed.**
- **Build-2 / Punch-list #4 ("`snapshotNames` 458 KB chunk → JSON asset"):** ❌ **Wrong diagnosis, right outcome.** The chunk was *named* `snapshotNames` (Vite picks the seed module's name), but the actual ~458 KB / 158 KB gzip mass was the **entire `@faker-js/faker` library** pulled in by `snapshotNames.ts:1` to power three trivial helpers: `shuffle`, `arrayElement`, `string.alphanumeric`. There was no data table to extract. Real fix: replace the three call sites with ~20 LOC of vanilla `Math.random` and drop the import. Bundle savings as predicted (~158.5 KB gzip), via a totally different mechanism. **Also retroactively justifies Round-1's `@faker-js/faker` removal from `package.json`** — without this fix that change would have broken `npm ci`. **Fixed.**
- **`@faker-js/faker` package-json removal (Round 1, Dead-3):** ⚠️ **Was a latent CI break until fixed in Round 4.** `package.json` had it removed but `web/src/app/utils/snapshotNames.ts:1` was still importing it; build only kept passing because `web/node_modules/@faker-js/` was still on disk from before the removal. Resolved transitively by Build-2 fix above; verify by re-running `npm ci` from a clean state.
- **Lat-3 / Punch-list #6 (`ToastsPresenter` debounce):** ❌ **Misdiagnosis — not a bug.** [`ToastsPresenter.tsx`](../../web/src/app/components/presenters/ToastsPresenter.tsx) does not "create a new toast per event." It is a derived-state reconciliation pattern: `pushNotification` is an upsert keyed by stable `decision.eventId`, and the dismissal loop reconciles toasts no longer in the current decision set. The real per-event work is upstream in [`usePlatformEventDecisions.ts:19-22`](../../web/src/app/hooks/usePlatformEventDecisions.ts#L19-L22) (Lat-7), and that recompute is already gated by Round 1's `eventsAreEqual` ref-identity fix. Adding a debounce here would introduce visible latency to real-time alerts (`audio.xrun`, `node.offline`, `failover.initiated`) for no measurable gain. **Skipped intentionally.**
- **Build-1 / Lat-1 / Punch-list #9 (`App.js` chunk split):** ❌ **Severity overstated, fix forbidden.** App.js is 629 KB / **174 KB gzip** — gzip transfer cost is what matters, and 174 KB on a Carbon + React + Router + Query shell is the expected floor (Carbon alone is ~120 KB gzip). The audit's two proposed fixes don't apply: (a) `ReactQueryDevtools` is **already** dynamic-imported and gated on `process.env.NODE_ENV !== 'production'` at [`App.tsx:49-51`](../../web/src/app/App.tsx#L49-L51), so Vite tree-shakes it from prod entirely; (b) `splitVendorChunkPlugin` / broader vendor splits are **explicitly forbidden** by a [HIGH] gotcha in [`docs/CLAUDE.md`](../../docs/CLAUDE.md) — past attempt caused `Cannot read properties of undefined (reading 'forwardRef')` because Carbon/Recharts/ReactFlow/MUI all ride the React init graph. Vite config's existing surgical manualChunks (`monaco`, `xterm`, `reactflow+dagre`, `framer-motion`) is the deliberate maximum-safe split. Outcome: bumped `chunkSizeWarningLimit` from 600 → 700 to clear the (cosmetic) build warning honestly and documented why in the config. The "Critical" framing in Lat-1 was wrong; severity should have been Low (cosmetic build noise). **Resolved by config; no chunk surgery.**

## Lens 1 — Architectural Design Flaws

**Total: 18** — Critical: 2 · High: 6 · Medium: 8 · Low: 2

### Arch-1 [Critical · L] God component: `SnapshotEditorPageContent`
- **Where:** [`web/src/app/pages/SnapshotEditorPageContent.tsx:1-9831`](../../web/src/app/pages/SnapshotEditorPageContent.tsx)
- **What:** 9,831-line single file combining routing, state, UI, modals, MIDI handling, audio config, real-time metrics, undo/redo, keyboard shortcuts.
- **Fix:** Decompose into ~15 modules: shell + grid + presets + routing + metrics + per-modal files. Migrate state to Zustand.

### Arch-2 [High · M] Device shells bypass `DeviceContextBanner` directive
- **Where:** [`MPX1Shell.tsx:44`](../../web/src/app/components/Devices/MPX1/MPX1Shell.tsx#L44), [`IntelFXShell.tsx:59`](../../web/src/app/components/Devices/IntelFX/IntelFXShell.tsx#L59), [`LCDShell.tsx:34`](../../web/src/app/components/Devices/LCD/LCDShell.tsx#L34)
- **What:** Each shell creates its own `*PageContext` with identical pattern instead of using `DeviceContextBanner` + `useDeviceNodeContext`. Violates CLAUDE.md §5 directive.
- **Fix:** Render `<DeviceContextBanner deviceKey="…" />` inside each shell; migrate UI state to dedicated hooks.

### Arch-3 [High · S] Prop drilling in `DeviceDetailRoute` tabs — ❌ NO LONGER VALID 2026-05-06 (cycle 57 re-verification, audit-overstated)
- **Where:** [`DeviceDetailRoute.tsx:181-193`](../../web/src/app/components/Devices/DeviceDetail/DeviceDetailRoute.tsx#L181-L193)
- **What:** `profile` passed through 5 TabPanels; will worsen as nesting grows.
- **Fix:** `<DeviceDetailContext>` wrapping Tabs with `{ profile, packSource, manifest }`.
- **Status check 2026-05-06:** the audit calls this "prop drilling" but there is no drilling chain — each tab is a sibling of `<TabPanel>` and receives only its immediate props. The actual prop counts per tab are: OverviewTab/AudioIoTab/BindingsTab take a single `profile` prop, DiagnosticsTab takes a single `packId`, LicenseTab takes 5 props all derived directly from `profile` + `packSource`. Adding a context to skip a single direct-pass is a net loss in clarity. The "will worsen as nesting grows" framing is speculative — none of the tabs render further nested consumers of `profile`. Closed as audit-overstated.

### Arch-4 [High · M] No state-management policy: Zustand vs `useState` vs React Query mixed
- **Where:** [`web/src/app/stores/`](../../web/src/app/stores/) (Zustand), [`MPX1MidiMapper.tsx:73-86`](../../web/src/app/components/Devices/MPX1/MPX1MidiMapper.tsx#L73-L86) (10 useState), [`SnapshotEditorPageContent.tsx:16-73`](../../web/src/app/pages/SnapshotEditorPageContent.tsx#L16-L73) (React Query).
